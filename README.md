# HackAlem AI — умный подбор подрядчиков

**Backend-сервис, который помогает выбрать до трёх event-подрядчиков из готового каталога и объясняет результат.**

Пользователь задаёт город, дату, формат мероприятия, категорию и бюджет. Сервис исключает неподходящих исполнителей, учитывает календарь занятости и ранжирует оставшихся. Дополнительные пожелания сопоставляются с описаниями подрядчиков через OpenAI embeddings; при отсутствии ключа или ошибке обращения к API предусмотрен резервный расчёт через TF-IDF.

Проект разработан для задачи **«Умный подбор подрядчиков (#79-lite)»** хакатона HackAlem AI. Это сервис рекомендаций, а не система бронирования. Интерфейс для проверки — Swagger UI, отдельный frontend не требуется.

> В текущей реализации AI используется для оценки соответствия текстов. Фильтрация и итоговая сортировка выполняются Python-кодом, а объяснения собираются из шаблонов и фрагментов профилей, без генеративной LLM.

## Быстрый запуск

### 1. Подготовить окружение

Для разработки использовался **Python 3.12**. Ограничение версии Python и зависимости проекта задаются в `pyproject.toml`, конкретные версии зависимостей — в `uv.lock`.

Нужен установленный менеджер проектов `uv`. Проверка:

```powershell
uv --version
```

Все последующие команды выполняются **из корня репозитория**, где находятся `pyproject.toml` и `uv.lock`.

Установить зависимости, не изменяя lock-файл:

```powershell
uv sync --locked
```

Команда подготовит проектное окружение. При использовании `uv run` вручную активировать `.venv` не требуется. Не нужно повторно выполнять `uv init` в уже подготовленном репозитории.

Проверить, что датасет расположен по пути:

```text
data/hackathon-dataset-anonymized.csv
```

Если исходный файл называется `hackathon dataset anonymized .csv`, при размещении в проекте переименуйте его в `hackathon-dataset-anonymized.csv`.

### 2. Настроить OpenAI — необязательно

Для семантического ранжирования через OpenAI создайте в корне проекта файл `.env`:

```dotenv
OPENAI_API_KEY=your_openai_api_key_here
```

Замените пример своим действующим ключом. Переменные загружаются через `python-dotenv`; ключ также может быть задан в окружении процесса.

Используемая модель задана в `semantic.py`:

```text
text-embedding-3-small
```

**Реальный `.env` нельзя добавлять в Git.** Для передачи настроек без секрета можно создать `.env.example` с содержимым:

```dotenv
OPENAI_API_KEY=
```

Без ключа приложение использует локальный TF-IDF при наличии пожеланий. Если `preferences` не переданы или равны пустой строке, текстовая оценка равна нулю и внешний API не вызывается. NVIDIA API в текущей реализации не подключён.

### 3. Запустить приложение

```powershell
uv run uvicorn hack_dbab4d08_ai_job_hunter.main:app --reload
```

Адреса локального сервиса:

```text
Swagger UI:    http://127.0.0.1:8000/docs
OpenAPI JSON:  http://127.0.0.1:8000/openapi.json
Health check:  http://127.0.0.1:8000/health
```

В Swagger откройте `POST /recommend`, нажмите **Try it out**, вставьте JSON из раздела с примерами и нажмите **Execute**.

`--reload` предназначен для разработки. Для демонстрации без автоматических перезапусков:

```powershell
uv run uvicorn hack_dbab4d08_ai_job_hunter.main:app
```

### 4. Запустить тесты

```powershell
uv run pytest -v
```

В текущем наборе — **6 тестов**. Последний локальный прогон при подготовке проекта завершился результатом:

```text
6 passed
```

Проверки не отправляют запросы в OpenAI. Подробности и границы покрытия описаны в разделе [«Тестирование»](#тестирование).

## Данные

Основа каталога — предоставленный организаторами анонимизированный датасет из **66 профилей**. В нём есть исполнители и площадки: ведущие, фотографы, флористы, банкетные залы и другие категории.

Календарь охватывает **23.09.2026–31.12.2026 включительно**, то есть 100 дней. У площадок также есть занятые даты. За пределами этого интервала приложение не делает предположений о доступности и отклоняет запрос при валидации.

| Поле CSV | Значение |
| --- | --- |
| `id` | Идентификатор профиля |
| `anon_name` | Вымышленное имя, в ответе API переименовывается в `name` |
| `categories` | Одна или несколько категорий подрядчика |
| `city` | `Алматы`, `Астана` или `Зарубежье` |
| `price_from_kzt` | Цена **«от»** в тенге за мероприятие |
| `event_formats` | Форматы мероприятий, с которыми работает подрядчик |
| `languages` | Языки работы |
| `max_hours` | Максимальное число часов присутствия; пустое значение означает неприменимость этого ограничения |
| `busy_dates` | Занятые даты в пределах календаря |
| `description` | Описание профиля на русском языке |
| `synthetic` | Признак синтетического профиля |
| `city_imputed` | Город был заполнен при подготовке датасета |
| `price_imputed` | Цена была заполнена при подготовке датасета |

В исходном наборе 13 профилей помечены как полностью синтетические. Эти флаги остаются в данных, но текущая схема карточки API их не возвращает.

При загрузке значения `categories`, `event_formats` и `languages`, разделённые символом `|`, преобразуются в списки. `busy_dates` становится множеством строк формата `YYYY-MM-DD`; дата запроса сравнивается с ними через `request.date.isoformat()`.

Каталог загружается при импорте приложения, один раз на процесс. Изменение CSV требует перезапуска приложения. Путь вычисляется относительно корня исходного проекта, поэтому папка `data/` должна сохраняться рядом с `src/`.

> Сравнение `price_from_kzt <= budget` подтверждает соответствие **стартовой цены** бюджету. Оно не гарантирует окончательную стоимость услуги после согласования деталей.

## API

### `GET /health`

Проверка доступности приложения и количества загруженных профилей.

```json
{
  "status": "ok",
  "contractors_loaded": 66
}
```

Этот маршрут не проверяет доступность OpenAI и не выполняет семантический поиск.

### `POST /recommend`

Принимает JSON и возвращает от нуля до трёх рекомендаций. Входная модель — `RecommendationRequest`, выходная — `RecommendationResponse`.

#### Параметры запроса

| Поле | Тип | Обязательное | Ограничение / поведение |
| --- | --- | --- | --- |
| `city` | string | Да | Только `Алматы`, `Астана`, `Зарубежье` |
| `date` | string → date | Да | `YYYY-MM-DD`, в пределах календаря датасета |
| `event_format` | string | Да | Один из шести поддерживаемых форматов |
| `category` | string | Да | Например, `Ведущий`, `Фотограф`, `Банкетный зал` |
| `budget` | integer | Да | Больше нуля, в тенге |
| `duration_hours` | integer или null | Нет | От 1 до 24 часов; при указании участвует в строгой фильтрации |
| `language` | string или null | Нет | `русский`, `казахский`, `английский`; предпочтение для рейтинга |
| `preferences` | string или null | Нет | До 500 символов; пожелания к стилю и особенностям работы |

Поддерживаемые форматы:

```text
свадьба, той, корпоратив, конференция, юбилей, день рождения
```

`city`, `event_format` и `language` проверяются через `Literal`: передавайте их в указанном написании. Категория пока остаётся свободной строкой. Нераспознанная категория, в том числе с опечаткой, приводит к `category_not_found`, а не к ошибке списка допустимых значений.

**Язык — мягкое предпочтение.** Если нужного языка нет в профиле, кандидат не исключается, но не получает языковой бонус. Это отличается от длительности, которая при указании проверяется как обязательное условие.

#### Пример запроса

```json
{
  "city": "Алматы",
  "date": "2026-10-15",
  "event_format": "свадьба",
  "category": "Ведущий",
  "budget": 1200000,
  "duration_hours": 8,
  "language": "русский",
  "preferences": "Хочу спокойного интеллигентного ведущего с ненавязчивым юмором"
}
```

| Поле | Смысл |
| --- | --- |

#### Бизнес-исходы и HTTP-коды

| Ситуация | HTTP | `status` |
| --- | --- | --- |
| Найден хотя бы один кандидат | 200 | `success` |
| В городе нет такой категории | 200 | `category_not_found` |
| Категория есть, но все исключены условиями | 200 | `no_matches` |
| Невалидные входные параметры | 422 | Ответ валидации с `detail`, не `RecommendationResponse` |

Ноль результатов — нормальный бизнес-исход, а не `500 Internal Server Error`.

## Алгоритм подбора

```text
JSON-запрос
    ↓
Проверка RecommendationRequest
    ↓
Есть категория в выбранном городе?
    ├── нет → category_not_found
    ↓ да
Жёсткие фильтры
    ├── никто не прошёл → диагностика → no_matches
    ↓
Язык + бюджет + длительность + текстовое соответствие
    ↓
Сортировка по score, цене и id
    ↓
TOP-3
    ↓
Объяснения + формирование RecommendationResponse
```

### Жёсткая фильтрация

Кандидат должен одновременно удовлетворять условиям:

```text
Город совпадает с запросом.
Категория присутствует в categories.
Формат присутствует в event_formats.
price_from_kzt <= budget.
Дата отсутствует в busy_dates.
Если duration_hours указаны:
    max_hours отсутствует ИЛИ max_hours >= duration_hours.
```

`max_hours = null` в этом датасете означает, что ограничение по присутствию не применяется, например для флористики, декора и сувениров. Это не интерпретируется как ноль часов.

В `filters.py` условия объединяются в одну булеву маску. Она применяется через `contractors.loc[mask].copy()`, сохраняя столбцы DataFrame и при пустом результате.

Высокий AI-балл не может вернуть кандидата, уже исключённого жёсткими условиями.

### Формула ранжирования

```text
score = language_score + budget_score + duration_score + 40 × semantic_score
```

| Компонент | Текущая логика |
| --- | --- |
| `language_score` | +30, если указанный язык есть в профиле; иначе 0 |
| `budget_score` | `20 × (budget − price_from_kzt) / budget`, с ограничением от 0 до 20 |
| `duration_score` | 0, если часы не указаны; +15 при точном совпадении с `max_hours`; +10 при запасе часов или неприменимом ограничении |
| `40 × semantic_score` | Вклад сходства пожеланий и описания; 0, если пожеланий нет |

Веса заданы вручную как эвристика MVP и не обучались на пользовательской обратной связи. Бонус за точное совпадение длительности — текущее проектное решение, а не доказательство превосходства такого кандидата.

Для Хаула из примера расчёт приблизительно такой:

```text
Язык:                  30
Бюджет:                20 × (1 200 000 − 1 000 000) / 1 200 000 ≈ 3,33
Длительность:          15
Текстовое сходство:     40 × 0,465 ≈ 18,60
Итого:                 около 66,94 с учётом неокруглённого сходства
```

Сортировка выполняется до округления:

```text
score              по убыванию
price_from_kzt     по возрастанию
id                 по возрастанию
```

После неё выбираются первые три записи. В ответе `score` округляется до двух знаков, `semantic_score` — до трёх.

При одинаковом каталоге, запросе и семантических оценках порядок воспроизводим. Переключение между OpenAI и TF-IDF может изменить оценки и порядок; абсолютная повторяемость между этими режимами текущей реализацией не гарантируется.

## AI, кэш и резервный режим

### Основной режим

В `semantic.py` пожелания пользователя и описания уже отфильтрованных кандидатов преобразуются в векторы моделью OpenAI `text-embedding-3-small`. Затем локально вычисляется cosine similarity.

```text
preferences → embedding запроса
                          ↘
                            cosine similarity → semantic_score
                          ↗
description → embedding профиля
```

Смысловое соответствие помогает различать близкие формулировки, а не только точные совпадения слов. Однако это оценка сходства, а не проверка истинности профиля или гарантия исполнения всех пожеланий. Высокий балл не подтверждает, например, отсутствие нежелательных конкурсов, если такого утверждения нет в исходном описании.

### Что кэшируется

`description_cache` хранит embeddings по тексту описания в памяти процесса.

| Сценарий | Обращения к API на уровне кода, без учёта повторов SDK |
| --- | --- |
| Есть новые описания | Один пакетный запрос для отсутствующих в кэше описаний и отдельный запрос для пожеланий |
| Все описания уже в кэше | Только запрос для пожеланий |
| Нет пожеланий | Нет обращений для семантического ранжирования |
| Не осталось кандидатов | Ранжирование не запускается, нет обращений |

Embeddings пользовательских пожеланий пока не кэшируются. Кэш описаний очищается при перезапуске и не разделяется между несколькими процессами приложения.

### Резервный TF-IDF

При отсутствии ключа или исключении во время обращения к OpenAI функция переходит к `TfidfVectorizer` и cosine similarity. При ошибке OpenAI в терминале выводятся сообщения:

```text
OpenAI embeddings failed: ...
Falling back to TF-IDF
```

Резервный режим использует словарное сходство, а не нейросетевое представление смысла. В текущем коде TF-IDF обучается на пожеланиях и описаниях кандидатов конкретного запроса.

Баллы двух режимов не стоит напрямую сравнивать как единую шкалу качества. Активный режим пока не возвращается отдельным полем API; по одному числу `semantic_score` нельзя достоверно определить, какой механизм сработал.

### Скорость и границы отказоустойчивости

Кэш убирает повторное вычисление описаний, но первый запрос с новыми профилями всё ещё обращается к внешнему сервису. Время ответа зависит от сети и API.

В текущей версии не задан специальный короткий `timeout` и не отключены стандартные повторы OpenAI SDK. Поэтому fallback выполняется после завершения неудачного обращения, а не обязательно сразу. Жёсткое выполнение всего запроса менее чем за 10 секунд пока не обеспечено.

TF-IDF также требует пригодного для векторизации текста: для полностью пустого или состоящего только из пунктуации корпуса отдельная защита пока не добавлена. Наличие fallback не следует трактовать как гарантию отсутствия любых ошибок.

## Объяснения и диагностика

### Как формируются объяснения

`explanations.py` собирает текст из проверяемых данных: стартовая цена и разница с бюджетом, доступность на выбранную дату по календарю, совпадение языка и достаточная длительность.

Если есть `preferences` и `semantic_score > 0.20`, добавляется выдержка из `description`. Текущая реализация выбирает первое предложение длиной не менее 20 символов и сокращает его примерно до 160 символов.

Порог `0.20` — эвристика, не откалиброванная оценка уверенности. Выдержка берётся из исходного профиля, а не генерируется LLM и не обязательно является наиболее релевантным пожеланию предложением.

### Как считаются отказы

Диагностика рассматривает только подрядчиков нужной категории в нужном городе. Для каждого учитывается **одна первая причина исключения** в таком порядке:

```text
wrong_format → over_budget → busy → duration
```

Поэтому суммы причин не задваивают подрядчиков. При `no_matches` сумма счётчиков соответствует числу рассмотренных кандидатов этой категории в городе, если диагностика и фильтры используют одинаковые условия.

**Важно:** `over_budget = 3` и `busy = 0` не означают, что все трое свободны. Они были отклонены по цене раньше, чем диагностика дошла до проверки занятости. Это статистика первых причин отказа, а не независимая проверка каждого ограничения для всех кандидатов.

Если подходят один или два подрядчика, возвращается именно это количество. Неподходящие кандидаты не добавляются ради заполнения TOP-3. Отдельное объяснение причины сокращённой успешной выдачи пока не формируется: `message` при успехе остаётся `null`.

## Тестирование

Тесты используют синтетический каталог из пяти профилей и `monkeypatch`, заменяющий `main_module.contractors`. В API-запросах не передаётся `preferences`, поэтому OpenAI не вызывается.

```powershell
uv run pytest -v
```

| Тест | Проверка |
| --- | --- |
| `test_busy_contractor_is_excluded` | Занятый в выбранный день подрядчик исключён |
| `test_over_budget_contractor_is_excluded` | В результате фильтрации нет цены выше бюджета |
| `test_api_returns_maximum_three_contractors` | API возвращает не более трёх карточек |
| `test_same_request_returns_same_order` | Повтор запроса без AI даёт одинаковый порядок ID |
| `test_category_not_found` | Отсутствующая категория даёт соответствующий бизнес-статус и пустой список |
| `test_different_dates_change_results` | На тестовом каталоге изменение даты меняет выдачу из-за занятости |

Исходный CSV всё равно должен присутствовать: он загружается при импорте `main.py` до подмены данных в тестах.

Шесть прошедших тестов подтверждают эти сценарии, но не покрывают качество embeddings, переключение на TF-IDF, задержку внешнего API, все случаи валидации или все варианты пустой выдачи. Отдельный интеграционный AI-тест и нагрузочный тест пока не добавлены.

## Сценарии демонстрации

### 1. Популярная категория и AI-ранжирование

```json
{
  "city": "Алматы",
  "date": "2026-10-15",
  "event_format": "свадьба",
  "category": "Ведущий",
  "budget": 1200000,
  "duration_hours": 8,
  "language": "русский",
  "preferences": "Хочу спокойного интеллигентного ведущего с ненавязчивым юмором"
}
```

Показать три карточки, итоговый рейтинг, текстовые оценки и основания выбора. Затем изменить пожелания на «энергичный ведущий с импровизацией и интерактивами» и сравнить оценки. Изменение пожеланий не обязано каждый раз менять TOP-3: остальные компоненты рейтинга тоже влияют на результат.

### 2. Редкая категория

```json
{
  "city": "Алматы",
  "date": "2026-10-15",
  "event_format": "свадьба",
  "category": "Флорист",
  "budget": 300000,
  "language": "русский"
}
```

Показать, что количество карточек ограничивается реальными совпадениями, а не искусственно дополняется до трёх. Пустой результат на особенно загруженную дату также должен обрабатываться как бизнес-исход.

### 3. Бюджет, при котором результатов нет

```json
{
  "city": "Астана",
  "date": "2026-10-15",
  "event_format": "свадьба",
  "category": "Фотограф",
  "budget": 10000,
  "duration_hours": 8,
  "language": "русский"
}
```

Ожидается `no_matches`, пустой список, текстовое объяснение и счётчики причин отказа.

### 4. Категории нет в городе

```json
{
  "city": "Астана",
  "date": "2026-10-15",
  "event_format": "свадьба",
  "category": "Декоратор",
  "budget": 3000000
}
```

Для исходного каталога ожидается `category_not_found`. При добавлении новых профилей ожидаемый результат нужно пересмотреть.

### 5. Проверка календаря

```json
{
  "city": "Астана",
  "date": "2026-10-15",
  "event_format": "свадьба",
  "category": "Фотограф",
  "budget": 400000,
  "duration_hours": 8,
  "language": "русский"
}
```

Повторить, изменив только `date` на `2026-10-16`. Сравнить ID и дату в объяснениях. Разные даты не обязаны всегда давать разный список: это определяется календарями конкретных профилей. Автоматический тест проверяет изменение выдачи на специально подготовленных данных.

### 6. Проверка валидации

В любом валидном запросе заменить дату на `2027-05-01` или бюджет на `0`. Ожидается HTTP `422` с описанием ошибки в `detail`.

### Короткое объяснение для защиты

> Сервис помогает выбрать из готового каталога, а не просто показывает длинный список. Python проверяет город, категорию, формат, стартовую цену, календарь и длительность. Среди допустимых кандидатов мы учитываем языковое предпочтение и смысл пожеланий через OpenAI embeddings. Описания кэшируются, а при недоступности API предусмотрен TF-IDF. Пользователь получает до трёх карточек с основаниями выбора или объяснение отсутствия результатов. Основные сценарии фильтрации и API проверяются шестью автоматическими тестами.

## Ограничения и развитие

Это локальный хакатонный MVP. Он не выполняет бронирование, не создаёт заявки, не уведомляет подрядчиков и не поддерживает оплату, авторизацию или пользовательские аккаунты.

Следующие пункты **пока не реализованы или требуют доработки**, а не являются заявленными возможностями:

| Область | Текущее ограничение / следующий шаг |
| --- | --- |
| Время ответа | Добавить короткие сетевые таймауты, контроль повторов и измерение полной задержки |
| Повторяемость AI | Фиксировать режим и результаты вычисления; переход OpenAI → TF-IDF сейчас способен изменить порядок |
| Прозрачность режима | Возвращать, какой механизм вычислил оценки: OpenAI, TF-IDF или без текстового ранжирования |
| Сокращённая выдача | Для 1–2 результатов добавить сообщение, почему вариантов меньше трёх |
| Объяснения | Сократить до требуемых 1–2 предложений; текущий шаблон может быть длиннее |
| Происхождение данных | Показывать `synthetic`, `city_imputed`, `price_imputed` в карточках |
| Языковые требования | Разделить строго обязательный язык и пожелание; сейчас реализовано только предпочтение |
| Текстовые поля | Нормализовать пробелы и обрабатывать крайние случаи TF-IDF |
| Кэш | Добавить постоянное хранение и кэш пожеланий; сейчас кэш описаний только в памяти |
| Качество рекомендаций | Проверить веса и текстовые оценки на размеченных примерах; текущие веса эвристические |
| Эксплуатация | Перед публичным запуском добавить защиту API, лимиты запросов, управление расходами и наблюдаемость |

Отсутствие бронирования и отдельного красивого UI соответствует границам исходной задачи. Остальные улучшения отделены от уже работающей реализации, чтобы документация не обещала непроверенные свойства.

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `FileNotFoundError` при загрузке CSV | Файл должен лежать в `data/hackathon-dataset-anonymized.csv`; важны точное имя и положение относительно `src/` |
| `ModuleNotFoundError` для пакета | Запуск из корня проекта, наличие `src/hack_dbab4d08_ai_job_hunter/__init__.py`, успешный `uv sync` и настройка пакета в `pyproject.toml` |
| `ImportError: RecommendationRequest/RecommendationResponse` | В `schemas.py` должны сохраняться обе модели и вспомогательные модели ответа |
| В Swagger показана старая схема | Убедиться, что запущен нужный модуль и у `/recommend` указан `response_model=RecommendationResponse`; перезапустить сервер и обновить страницу |
| OpenAI не отвечает или отклоняет запрос | Проверить настройки ключа, доступ к модели, сеть и ограничения API; читать сообщение о fallback в терминале |
| Запрос долго выполняется | Внешние обращения и стандартные повторы SDK могут задерживать переход к резервному режиму |
| После правки `.env` режим не изменился | Перезапустить процесс: клиент создаётся при импорте `semantic.py` |
| HTTP `422` | Проверить написание допустимых значений, положительный бюджет, диапазон даты и длительность |

Не публикуйте диагностические логи без проверки: в них могут быть сведения о проекте и запросах.

## Безопасность и публикация

API-ключ читается из окружения и не должен находиться в исходном коде или README. В `.gitignore` должны быть как минимум:

```gitignore
.env
.env.*
!.env.example
.venv/
__pycache__/
.pytest_cache/
```

`uv.lock`, `pyproject.toml`, исходный код, тесты и разрешённый к распространению датасет нужны для воспроизводимого запуска. `uv.lock` не следует игнорировать.

Перед публикацией проверить:

```powershell
git status
git check-ignore .env
git ls-files -- .env
uv run pytest -v
```

Если `git ls-files -- .env` выводит имя файла, он уже отслеживается: одного изменения `.gitignore` недостаточно. Удалите его из индекса, сохранив локально:

```powershell
git rm --cached .env
```

Если реальный ключ уже попал в коммит или был раскрыт, отзовите его и создайте новый. Удаление файла в последнем коммите не убирает секрет из предыдущей истории.

При использовании OpenAI наружу отправляются тексты пожеланий и описания выбранных кандидатов. Не вводите в `preferences` секреты или ненужные персональные данные.
